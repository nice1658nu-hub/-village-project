# แผนทดสอบและประเมินระบบ

## เกณฑ์ผ่าน

ฟังก์ชันหลักต้องทำงานถูกต้อง ไม่มีข้อมูลข้ามสิทธิ์ และไม่ทำให้หน้าเว็บค้างหรือเป็นหน้าขาว คะแนนความพึงพอใจเฉลี่ยควรไม่น้อยกว่า 3.51 จาก 5 หรือเป็นไปตามเกณฑ์ที่อาจารย์กำหนด

## กรณีทดสอบหลัก

| รหัส | กรณีทดสอบ | ผลที่คาดหวัง |
|---|---|---|
| T01 | สมัครด้วยข้อมูลครบ | ได้บัญชีสถานะรออนุมัติ |
| T02 | เข้าระบบก่อนอนุมัติ | ระบบปฏิเสธและอธิบายสถานะ |
| T03 | ผู้ดูแลอนุมัติ แล้วลูกบ้าน Login | เข้าระบบได้ตามบทบาท |
| T04 | ลูกบ้านแจ้งเหตุพร้อมพิกัด/รูป | บันทึกและปรากฏในฝั่งผู้ดูแล |
| T05 | กรองเหตุด้วยหมวด/สถานะ/วันที่ | แสดงเฉพาะรายการตรงเงื่อนไข |
| T06 | ผู้ดูแลมอบหมายงาน | เจ้าหน้าที่เห็นงานที่ได้รับ |
| T07 | เจ้าหน้าที่ส่งรูปปิดงาน | ผู้ดูแลและลูกบ้านเปิดดูได้ |
| T08 | ผู้ใช้ทั่วไปเรียก API ผู้ดูแล | ได้ 403 Forbidden |
| T09 | กู้รหัสผ่านด้วยอีเมล | ได้ลิงก์และตั้งรหัสใหม่ได้ |
| T10 | ดาวน์โหลด PDF/Excel | ได้ไฟล์ เปิดอ่านได้ และข้อมูลตรง |
| T11 | เปิดบนมือถือ/แท็บเล็ต/คอม | เนื้อหาไม่ล้นและปุ่มใช้งานได้ |
| T12 | อัปโหลดไฟล์ผิดชนิด/ใหญ่เกิน | ระบบปฏิเสธพร้อมข้อความชัดเจน |

## การทดสอบอัตโนมัติ

ดับเบิลคลิก `CHECK-SMART-VILLAGE.cmd` เพื่อเปิด MySQL รัน Backend tests และสร้าง Frontend production build หากจบด้วย `SmartVillage readiness check passed` ถือว่าการตรวจอัตโนมัติผ่าน

## แบบประเมินผู้ใช้ตัวอย่าง

ใช้มาตราส่วน 5 ระดับ: 5 มากที่สุด, 4 มาก, 3 ปานกลาง, 2 น้อย, 1 น้อยที่สุด

1. ระบบใช้งานง่ายและเมนูเข้าใจได้
2. ขั้นตอนแจ้งเหตุสะดวก
3. แผนที่และตำแหน่งช่วยระบุจุดเกิดเหตุได้
4. การติดตามสถานะมีความชัดเจน
5. ข่าวและการแจ้งเตือนมีประโยชน์
6. หน้าจออ่านง่ายบนอุปกรณ์ที่ใช้
7. ความเร็วของระบบเหมาะสม
8. ความพึงพอใจโดยรวม

ควรเก็บบทบาท อุปกรณ์ และข้อเสนอแนะปลายเปิด แต่ไม่เก็บข้อมูลส่วนบุคคลเกินความจำเป็น
